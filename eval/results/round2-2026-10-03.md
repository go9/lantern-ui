## What discriminated

- **ticket-index** separated A from B/C on the weighted rubric: A scored 96/100 (3 lantern components, below its task-scaled component bar), while B and C scored 100/100 (6 components). Both docs conditions cleared the component bar; C did not improve on B.
- **ops-dashboard** exposed a consistent functional-fidelity miss despite 100/100 weighted scores: A missed pagination and filter chips; B and C missed pagination. The task’s expected pagination behavior was not implemented in any condition. C improved the block checklist by one item over A, but matched B.
- The other seven tasks were at 100/100 for all three conditions and passed their block checks. They did not discriminate among conditions under this rubric.

## Failure categories and examples

1. **Functional/recipe fidelity (3 of 27 condition-runs):** ops-dashboard failed block checks in A, B, and C. A omitted both pagination and filter chips; B/C omitted pagination. This demonstrates that the weighted score can remain at 100 while a concrete expected behavior is missing.
2. **Accessibility smoke findings (66 axe violations across 27 runs):** mean counts were A 1.67, B 2.78, C 2.89 per run. The most frequent rules were missing main landmarks and content outside landmarks; color contrast also recurred. One C dashboard run reported an `aria-prohibited-attr` violation. These are axe rule counts, not counts of affected elements.
3. **Component-use bar:** ticket-index A used three lantern components (`list_row`, `status_glyph`, `priority_glyph`) against a task-scaled bar of four and scored 96. B/C used six and scored 100.
4. **Round-one version skew (retained as failure data):** `ticket-index-C-r1` compiled against lantern_ui Hex 0.8.3 and failed with `undefined function stack/1`. The recipes’ `<.stack>` call is supported by the current package and is imported by `use LanternUI`; the failure was the stale package pin, not a missing import instruction. That run remains in the round-one data and is not counted in the 27-run table. The dead themed-preview C rep-1 was rerun successfully on the round-two pin: 100/100, compile pass, zero lint findings, all 4/4 blocks, 2 axe violations, screenshot ok.

## Verdict

C does **not materially beat A**. The average weighted score is A 99.56, B 100, C 100; C’s only clear edge over A is one more dashboard block check, but it still misses pagination and offers no advantage over B. The extra C guidance did not resolve the hardest functional miss, and its mean axe count was slightly higher than B’s. With most weighted scores at ceiling, this round provides one component-use signal and one repeated block-fidelity signal, not evidence that the full C bundle reliably improves first-pass behavior. The task rubric should give pagination and URL/state behavior stronger direct functional checks in a future round.
